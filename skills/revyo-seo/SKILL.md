# Revyo SEO and discovery

Use the relevant workflow as public-site work reaches it. A new landing page needs
working metadata and share assets; a small unrelated UI edit does not require a
site-wide audit or a new brand.

- Existing indexing, crawl, metadata, or ranking issues:
  [seo-audit](../seo-audit/SKILL.md).
- A requested family of pages built from templates/data:
  [programmatic-seo](../programmatic-seo/SKILL.md).
- Content visibility or citations in AI search:
  [ai-seo](../ai-seo/SKILL.md).
- Public-site or MCP technical readiness for agents:
  [is-agentic](../is-agentic/SKILL.md).
- Missing/broken share cards, favicons, or brand foundations:
  [revyo-brand-social](../revyo-brand-social/SKILL.md).

Keep audit and programmatic SEO separate: diagnosing existing pages is different
from creating a page family. Use both only when the requested work crosses those
boundaries. Brand/social assets are another boundary, not a reason to generate
search pages.

For public-page metadata and indexing changes, use
[implementation checks](references/public-pages.md). Keep findings tied to exact
URLs, dates, and observed behavior. Distinguish technical eligibility, agent
readiness, search performance, and citation visibility. No score or file promises
rankings. Unavailable analytics can limit a performance conclusion without blocking
source changes or technical checks.
