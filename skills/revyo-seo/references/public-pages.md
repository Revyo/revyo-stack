# Public-page SEO checks

For changed public pages, check meaningful titles/descriptions, canonical URLs,
index directives, visible headings/copy, internal links, and appropriate structured
data. Read the response and rendered page where needed; absence from a text-only
fetch is not proof that JSON-LD or metadata is missing. Structured data describes
the actual page content and product; do not invent ratings, social profiles, or claims.

Use the actual public origin. Sitemaps contain canonical, indexable, successful
public URLs; keep account/token/private flows out. A `noindex` directive must be
retrievable to be seen; robots blocking is not access control. Keep sitemap dates
honest: substantive content changes, not a new timestamp on every request.

For generated page families, demonstrate distinct intent, useful page-specific
data, examples, and navigation before expanding. Repeated layout alone does not
establish spam, and there is no invented safe page-count or similarity threshold.
Use current [Google spam policies](https://developers.google.com/search/docs/essentials/spam-policies)
and [canonicalization guidance](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls)
for the actual finding. Do not invent keyword volumes or traffic forecasts when
Search Console/keyword data is unavailable.

For AI visibility, follow [Google’s AI guidance](https://developers.google.com/search/docs/appearance/ai-features)
where Google is the target; other platforms need their own current primary evidence.
Special AI files are not a requirement for Google’s AI features. Public Markdown,
pricing data, or discovery endpoints can help a concrete retrieval workflow without
becoming a universal ranking rule.

Is Agentic results are dated snapshots. Check the exact target and `scanned_at`,
corroborate older findings with current responses, and distinguish a fresh score
from an old report returned by the API/CLI. Do not wait indefinitely or claim a
new score without a new timestamp. Submit only appropriate public targets.

Verify the affected pages and share assets locally, then verify the actual public
origin when deployment is in scope. Run relevant project checks and report any
unverified external boundary. Do not deploy merely because a skill was selected.
