# Revyo engineering

Select guidance by the work underway; explicit invocation is optional.

- Bug diagnosis: [diagnosing-bugs](../diagnosing-bugs/SKILL.md).
- Code structure and seams: [codebase-design](../codebase-design/SKILL.md).
- Architecture decisions: [architect](../architect/SKILL.md).
- Scoped implementation: [implement](../implement/SKILL.md); use
  [implement-spec](../implement-spec/SKILL.md) when a specification already exists.
- Requested test-first work: [matt-tdd](../matt-tdd/SKILL.md).
- Code review: [code-review](../code-review/SKILL.md); use
  [interrogate](../interrogate/SKILL.md) for requested adversarial review.
- Understanding behavior or rationale: [how](../how/SKILL.md) and
  [why](../why/SKILL.md), respectively.
- Technical prose: [technical-writing](../technical-writing/SKILL.md).
- A nontrivial task needing a broader workflow: [poteto-mode](../poteto-mode/SKILL.md)
  provides a playbook. Skip it when a focused skill handles the task.

Keep process proportional. Use available tools and configured models; optional
Cursor-specific agents or plugins do not prevent direct work. Preserve the user's
scope and authorization. Complete the requested behavior and the checks needed
to establish it; avoid turning every small edit into a full review program.
